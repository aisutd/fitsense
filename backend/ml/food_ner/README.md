# Food recogniser (spaCy NER)

Finds the foods, amounts and units in a meal description so the backend can look up nutrition in
USDA FoodData Central. The model never produces nutrition numbers.

```
"I had a [3|QTY]-[egg|FOOD] [omelette|FOOD] and a [large|UNIT] [latte|FOOD]"
```

| Label | Meaning | Examples |
|---|---|---|
| `FOOD` | a food or dish, including words that are part of its name | `greek yogurt`, `iced coffee`, `tofu stir fry` |
| `QTY` | numbers, number words, fractions, ranges | `3`, `two`, `1/2`, `half`, `a couple`, `a few`, `2-3` |
| `UNIT` | measures, containers, sizes | `cups`, `g`, `slice`, `bowl`, `scoop`, `large` |

The trained model lives in `backend/app/food/model/` and is loaded by `app/food/parser.py`, which adds:

1. a **food-list matcher** (`app/food/data/foods.json`) that fills in known foods the model missed,
2. **rules** that attach amounts/units to foods ("2 slices of toast", "chicken (150 g)", "2 bacon strips"),
3. **recipe expansion** (`app/food/data/recipes.json`), e.g. omelette → eggs + oil (assumed) + cheese (assumed).

## How it was trained

- **Model:** spaCy 3.8, blank English, `tok2vec` + `ner` (CPU "efficiency" config, no word vectors), about 6 MB.
- **Training data:** 9,000 sentences generated by `generate_data.py` from templates ("I had {items} for {meal}",
  "2 cups of …", "half a …", "a 3-egg …", "2 bacon strips", ranges, lowercase typing, …) filled with 660 food names:
  the foods in `foods.json` plus ~250 training-only names for variety.
- **Dev set:** 1,500 generated sentences using 15% of the food names that were held out of training, so model
  selection rewards recognising foods it hasn't seen.
- **Test set:** `test_set.txt`, 107 hand-written sentences that are never used for training. About a third of the foods
  in it (kimchi, pho, shakshuka, kombucha, …) are not in `foods.json`, and the generator refuses to use them.

## Results (hand-written test set, exact span match)

| Setup | Overall F1 | FOOD F1 | QTY F1 | UNIT F1 | Known foods found | Unseen foods found |
|---|---|---|---|---|---|---|
| Food list + rules only (no ML) | 79.4% | — | 100% | 95.1% | 99.2% | **0%** |
| Model v1 | 95.0% | 96.2% | 89.2% | 95.1% | 96.7% | 95.3% |
| Model v2 | 98.0% | 97.3% | 100% | 100% | 98.3% | 95.3% |
| **Model v3 (shipped)** | **98.6%** | **98.4%** | **100%** | **98.3%** | **99.2%** | **96.9%** |

v1 → v2 came from adding training patterns the first model never saw (`a 3-egg omelette`, `a few`, `2-3 cups`,
`2 bacon strips`, words after the meal such as "on the way to class"). v2 → v3 added food-free sentences ("went for a
run today", "skipped breakfast"), surrounding context ("after the gym, I had …") and leading words ("another banana",
"leftover lasagna"): v2 tagged "went" and "run" as foods, v3 finds nothing in those sentences and now gets
"acai bowl" / "poke bowl" right. v3 was trained for 6,750 steps and the best dev checkpoint (step 4,750) is shipped.
The food list adds nothing measurable on top of the model here because the model already finds the known foods; it
stays as a safety net.

**Honesty notes:** after the first evaluation run, 7 test labels were corrected because compound dish names had been
split inconsistently (e.g. `[spinach][omelet]` → `[spinach omelet]`, matching `[chicken burrito]`). v1 scored 91.0%
F1 on the original labels and 95.0% on the corrected ones. The dev score (~98%) is from generated sentences and is
optimistic; trust the test-set numbers.

**Known weaknesses:** dishes joined by "and" ("biscuits and gravy" splits in two), and the model sometimes keeps a
piece word inside the food ("2 [bacon strips]"); `parser.py` splits trailing strip/slice/piece words back off. Measures
from other logs can be tagged as food ("slept 8 [hours]"); the parser drops those. Typos are only partly handled.

## Retraining

From `backend/`, with a virtualenv that has `requirements-dev.txt` installed:

```bash
python ml/food_ner/resolve_lexicon.py            # only if you added foods (needs FDC_API_KEY)
python ml/food_ner/generate_data.py              # writes ml/food_ner/corpus/
python -m spacy train ml/food_ner/config.cfg --output ml/food_ner/output --paths.train ml/food_ner/corpus/train.spacy --paths.dev ml/food_ner/corpus/dev.spacy
python ml/food_ner/evaluate.py --model ml/food_ner/output/model-best
cp -r ml/food_ner/output/model-best/. app/food/model/    # ship it if the test-set scores improved
```

Training takes about 20 minutes on a laptop CPU (v3: 22 minutes). `corpus/` and `output/` are git-ignored.

## Adding foods

1. Add a line to `app/food/data/foods.json` (`name`, `aliases`, `query`, `category`).
2. Run `resolve_lexicon.py`, check the printed FDC match, and fix the `query` (or set `fdc_id` and `"pinned": true`) if
   it picked the wrong food. For cooked foods pick the **"no added fat"** version: USDA's "NFS" entries for beans,
   lentils, egg whites etc. include cooking fat (a cup of "Beans, NFS" is 350 kcal vs 245 plain), and oil or butter is
   logged as its own ingredient.
3. Optionally add a recipe to `recipes.json` for dishes people would want to adjust ingredient by ingredient.
4. Retrain so the model sees the new names (the food-list matcher picks them up immediately either way).
